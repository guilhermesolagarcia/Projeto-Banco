## 2. Decisões e o porquê

- **O seletor do "Não julga" não usa JavaScript.** São dois `radio` nativos e o CSS reage com `:has()`. Teclado, foco e leitor de tela vêm do navegador, e o selo "0 kB de JS de animação" continua verdadeiro.
- **Mudança de rumo, no fim do dia:** o Motion entrou também na landing, por decisão do dono do projeto. O selo "0 kB" saiu do README. A troca de cenas do "Não julga" continua CSS puro (funciona antes de qualquer script); o Motion só faz a pílula deslizar. Custo medido: ~27 kB comprimidos na landing, mais ~6 kB carregados depois.
- **O Tailwind só gera classes escritas por extenso.** Uma classe montada com template string (`${prefixo}:opacity-100`) não existe no CSS final.
- **Uma fonte única para o exemplo da Marina** (`src/features/landing/example.ts`). A crítica achou quatro datas que se contradiziam. Agora "hoje" (23/11) e o salário (5/12) moram num arquivo só, e toda data é calculada a partir deles. A SPEC foi ajustada para o mesmo "hoje".
- **A exceção do laranja.** A regra "âmbar nunca é fundo de seção" continua valendo, com uma exceção escolhida: o fechamento. Branco sobre o âmbar da marca dá 2,45:1 e reprova; sobre o laranja queimado `#B5570C` dá 4,85:1 e passa. Por isso o fechamento usa o tom mais escuro.
- **Prevenir em vez de avisar.** O simulador agora só aceita números, ponto e vírgula, com teto de R$ 9.999.999,99. Impedir o erro é melhor do que mostrar uma mensagem depois.
- **Fundos alternados para separar seções**, como a apple.com faz, em vez de linhas divisórias.

## 3. A crítica do `impeccable`

Nota **25/32 (boa)** e nenhum problema mecânico no detector. As sete correções:

1. Datas vindas de uma fonte única (P1).
2. Avisos sem repetir o simulador (P1).
3. Rótulo com bolinha só onde ajuda a se orientar.
4. Fechamento retomando a promessa do começo.
5. Simulador legível em 320 px e sem entradas inválidas.
6. Seletor começando no banco comum.
7. "Como funciona" no menu, "Conta demo · Sem cadastro" no hero, "Em breve 3D" sem cara de botão.

## 4. Erros e lições do dia

- **Cache do servidor de desenvolvimento.** Um token novo no `@theme` não chegou ao CSS, e a seção ficou com texto branco sobre fundo branco. A solução foi parar o servidor, apagar `.next` e rodar `npm run dev` de novo. **Lição:** quando o código está certo e a tela não muda, desconfie do cache.
- **Parar a tarefa não parou o Next.** O processo filho continuou rodando na porta 3000. Foi preciso encerrá-lo pelo PID.
- **`rotate-45` no Tailwind 4 usa a propriedade `rotate`, não `transform`.** O `transition-transform` não animava o giro do "+".
- **O `sed` apaga a barra invertida.** Uma regex `[^\d.,]` virou `[^d.,]`. Foi pega antes do commit. Para editar código com símbolos, o editor é mais seguro que o `sed`.
- **Ferramenta de busca enganada.** O CSS de desenvolvimento vem quebrado em várias linhas, e um `grep` de uma linha só "não achou" regras que estavam lá.

### Decisões e o porquê

- **Uma fonte só de dados.** A landing, o simulador e o painel leem os mesmos números, calculados pelas regras. Mudar um gasto em `marina.ts` muda o site inteiro, e `npm run check:insights` avisa se a história da landing quebrar.
- **A Regra 3 foi revisada.** A tolerância de 10% fazia o detector perder a assinatura justamente quando ela ficava mais cara. Agora cada cobrança é comparada com a anterior (até 20%), e a alta mostrada é a que já aconteceu.
- **Cores de categoria calculadas, não escolhidas no olho.** O validador da skill de dataviz reprovou a primeira paleta (verde ao lado de laranja some para daltônicos). A ordem foi trocada até passar. Cada categoria tem sempre a mesma cor.
- **Os dados da Marina não vão para o navegador do visitante da landing.** Componentes de cliente recebem só os números de que precisam, por props.

### Erros e lições

- **Um componente que devolve `null` no servidor pode sumir com a página.** Com Cache Components, o Next descartou a página protegida e o painel ficava em branco. Solução: desenhar sempre e esconder (`hidden`) até o navegador confirmar a sessão.
- **O MSW se recusa a carregar no servidor** (`"node": null` no pacote). O painel passou a ser carregado só no navegador (`next/dynamic` com `ssr: false`), com o esqueleto vindo do servidor.
- **O MSW 3 mudou nomes e regras.** `onUnhandledRequest` virou `onUnhandledFrame` (o TypeScript pegou), e ligar o worker duas vezes dá erro. A "trava" de ligar uma vez passou a morar junto com o próprio worker.
- **Ctrl + Shift + R desliga os service workers.** Para as telas que usam o MSW, o certo é F5 comum.
- **Servidores de teste esquecidos ocupam a porta.** Uma medição saiu errada porque um servidor antigo ainda respondia. Sempre conferir se o servidor novo subiu de fato.
- **Ler a tipagem do pacote antes de usar uma versão nova.** Motion 14 e MSW 3 eram mais novos que o meu conhecimento; conferir os nomes no próprio `node_modules` evitou chutes.
